# BACnet IO 1.1.4-dev — recovery and network-time prerelease

This cumulative prerelease publishes the firmware development changes since
1.1.0. It is not a claim that automatic supervisory command restoration,
physical relay contacts, or full installation latency have passed acceptance.

## Changes

- Confirmed-COV recovery requests a fresh current value after transaction
  exhaustion, without replaying old payloads, extending subscriptions, or
  writing another device's points.
- Relay-driver recovery preserves the latest effective command through mutex
  timeouts and verifies the TCA9554 latch and pin direction. Diagnostics expose
  desired, applied, and register state separately.
- BACnet Device Restart Procedure notifications use persistent configurable
  recipients, bounded attempts, frozen boot timestamps, and per-destination
  diagnostics. Startup/link-return I-Am announcements have bounded retries.
- An NTP clock defaults to `pool.ntp.org`. The authenticated web interface
  supports persistent server and timezone changes without a reboot, common
  timezone presets, custom POSIX rules, and clock-quality diagnostics.
- Clock handling includes validated samples, warm-reset holdover, BACnet
  local-time/UTC-offset/DST properties, and safe ownership of asynchronous DNS
  work. NTP runs independently of BACnet and relay processing. Ordinary NTP
  is not authenticated NTS.
- The release also includes the previously merged authenticated command trace,
  improved soak diagnostics/offline review, and project development guidance.
- CI initializes pinned BACnet sources, explicitly selects modern host-test
  Python, and runs the new embedded time-settings browser test.

## Validation and limits

Host tests cover 102 Python checks plus the C scenario suites, including
actual-driver fault injection, confirmed-COV delivery, restart encoding and
persistence, clock validation/retention/DNS behavior, and time configuration.
The build uses ESP-IDF 5.5.4 and the unchanged pinned bacnet-stack 1.6.0.
Release publication is gated on the final GitHub firmware, host, and browser
checks. Release archives are clean CI builds; they are not byte-identical to
the earlier development build used for the limited field checks below.

Limited field checks on two controllers passed NTP synchronization, editable
web settings, BACnet clock properties, and warm-reboot persistence. An
independently decoded restart packet had the expected properties/timestamp.
A one-second pulse on an unused output was acknowledged in approximately
5 ms and verified at the driver register in approximately 25 ms. This is not
independent physical-contact feedback or a switch-to-door measurement.

Automatic supervisor output-command replay was not observed during two
output-controller reboot windows. Separate host test-safety tooling restored
freshly verified demand about 23 seconds after boot; that tooling is not part
of this firmware and is not an automatic-restoration fix. Later supervisor
replay was not measured after that intervention. Input-to-supervisor-to-output
loop timing, full cold-power/fault recovery, all electrical contacts, and a
new version-specific 24-hour endurance run remain outstanding.

No Metasys configuration or point writes were needed for this software work.
The firmware does not retain BACnet priorities, force supervisor logic to run,
or enable relay-state restoration as a shortcut. Existing boot output policy,
configuration, and commissioning keys are preserved on upgrade.

## Installation

Download the ZIP or tar.gz asset and verify its checksum. For Ethernet OTA,
upload `v1.1.4-dev/firmware-ota.bin` through the controller's authenticated
firmware-update page. The package also includes initial/individual flash
images, a manifest, checksums, and dependency licenses. Follow
[the installation guide](../BROWSER_INSTALLER.md) for supported flashing methods.

Plan for an output interruption during reboot. Do not assume the supervisor
will reassert its commands automatically; establish an authorized recovery
procedure before upgrading a controller connected to field hardware.
This prerelease does not replace the browser installer's recommended stable
version. Site captures, credentials, and raw deployment reports are not public
release assets.
